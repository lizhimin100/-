## 写作公式库（基于本项目特制）

### 一、爽点公式（核心引擎）

#### 【智商碾压】
主角在信息不完整的情况下，观察到对手忽略的细节 → 推导出对手真实意图或弱点 → 制定针对性的反制方案 → 对手措手不及 → 结尾有一句冷静的内心评价

#### 【资源循环爽】
主角投入少量资源 → 通过改造体体系转化为战力/资产 → 新战力再去获取更多资源 → 循环闭环 → 展示每一环的转化链条

#### 【隐藏实力暗爽】
外部视角：主角实力有限 → 内部视角：主角掌握了一击必杀的底牌 → 危机逼近，读者知道主角能应对而外部不知道 → 以最低调高效的方式解决，不暴露真实实力

#### 【认知差碾压】
两方掌握同一信息但解读深度完全不同 → 对手看到第一层（表面）→ 主角看到第三层（本质+延伸+对自己有利的操作空间）→ 对手基于浅层理解被主角预判

### 二、叙事公式（结构引擎）

#### 【单线推进式】
接续上章 → 主角行动解决一个问题 → 过程中获得新信息 → 调整判断 → 阶段性结果 → 新问题出现（钩子）

#### 【双线穿插式】
A线推进（主角主体行动）→ B线碎片（改造体共享视野/意念汇报/环境感知）→ A线与B线联动 → 主角调整策略 → 双线结果叠加 → 钩子

#### 【日常缓冲式】
非高强度冲突的过渡章节 → 主角与艾莉丝的互动 → 领地建设日常 → 多处信息碎片被引入但不激化 → 章末有微妙的不安感（暴风雨前的宁静）

### 三、微观写作规则

#### 每一章正文必须包含的元素
1. **开头锚定**（1-2段）：接续上章结尾状态，用环境、动作或内心描写自然衔接
2. **核心推进**（主体）：本章要解决什么问题/获得什么信息/做出什么决策
3. **思考过程展示**：情报分析 → 风险评估 → 资源盘点 → 方案择优的完整链条
4. **数据点插入**（至少1处）：魔力消耗、属性对比、改造体数量、资源清单等数据化描述
5. **章末钩子**（最后1-2段）：悬念/信息/情绪三种类型之一，自然生长自本章情节

#### 章节内场景切换分隔规则
- **场景/时间/空间/视角切换时**，统一使用`\n\n\n`（即两个换行符+一个空行，正文间一个完整的空行间距）作为分隔标识
- 不加任何分隔线（如`---`、`***`、`——`等），也不加任何文字标注
- 分隔前后的段落各自独立成段，末尾不需要句号收束，直接在段落结束后空行即可
- 示例格式：
  ```
  李星河收回目光，转身走下阁楼。
  
  他回到书房，重新坐下。
  ```
- 无分隔线规则背后的逻辑：让场景切换的视觉停顿完全由空白间距承载，保持正文的干净利落

#### 语言风格约束

**基调定位：**
- 冷静算计 + 数据驱动 + 隐藏实力暗爽 + 滚雪球满足感，四大核心基调贯穿全文
- 语言硬朗干脆，不拖泥带水，每个段落都有推进情节或塑造人物的功能

**句式和节奏：**
- 以中短句为主，配合偶尔的短句独段制造节奏变化（如「砰！」「稳了。」「神仙打架，别溅我一身血就行。」）
- 善用**逗号**串联动作链和思考链、**破折号少用、慎用**、**省略号**制造暂停感、**感叹号**强化爆发时刻
- 避免通篇句号导致的节奏沉闷，通过标点的组合使用模拟出阅读的呼吸感
- 在高潮段落（战斗、突袭、公布底牌）使用短句+分段+拟声词的叠加手法，营造紧张压迫感

**叙事视角与语气：**
- 严格限知第三人称，始终锚定主角李星河的所见所感所知
- 主角内心活动以「分析推演」为主，「情绪感慨」为辅——理性计算占比约70%，个人情绪占比约30%
- 偶尔打破第四面墙的幽默吐槽需克制使用（平均每5-8章出现1次），并符合主角前世博士生的学术冷幽默特质，如「这算不算一语双关？」——点到即止，不刻意搞笑

**信息密度策略：**
- 采用「行动中暴露信息」原则，避免静态的信息搬运（如大段背景介绍或设定说明）
- 黄金比例建议：叙事推进约40% + 角色互动与对话约25% + 思考/分析展示约25% + 环境/氛围描写约10%
- 情报/数据类内容（预知之环情报、属性面板、改造体数据）须包裹在「主角为何需要这个信息→信息带来了什么变化→主角如何利用这个信息」的叙事链条中，而非单独罗列

**悬念与钩子技巧：**
- 章末钩子的三种来源：（1）一个新信息的出现「预知之环冷却快结束了」（2）一个行动的潜在后果「现在，才是真正的开始」（3）一个情绪的余震，用环境或动作收尾，如「李星河看着窗外渐渐暗下来的天色」
- 钩子拒绝生硬插入，必须自然生长自本章的最后一波推进——让读者觉得「这里断章太坏了但我必须追下去」

**对话写作原则：**
- 以简短对话推进情节为主，避免超过连续5轮的问答式对话
- 每句对话至少承担以下一个功能：（1）传递信息（2）展现人物性格（3）制造冲突或张力（4）调节叙事节奏
- 对话间的动作/神态插入控制在1-2句，不打断核心对话的节奏感
- 角色语言风格锚定表（续）：

| 角色 | 语言风格 |
|:----:|:---------|
| 李星河 | 冷静理性，话中有算力，用词精确，偶尔带前世博士生的学术冷幽默（如「蝗兵」的命名、「撒币」的双关） |
| 艾莉丝 | 温和理性，带精灵的疏离感和知识分子的克制感，含蓄表达为主，情绪流露真诚 |
| 洛鸢 | 商业化但带试探，措辞精确，每句话都有潜台词，善于在对话中埋合作锚点 |
| 塞瑞娜 | 简洁直接，不加修饰，生存至上主义的直白 |
| 改造体 | 服从性高，回答精炼，不废话，被改造后保留部分原有意识的特点（如赵奎的精明藏在忠诚之下） |
| 底层领民/难民 | 质朴/粗俗，带口语化特征（口头禅、语气词），有时承担世界观侧面展示功能 |

**场景描写优先级：**
1. 与情节推进直接相关的描写（如战斗环境、关键建筑、人物表情）
2. 能体现世界观独特性或氛围感的描写（如兽潮之后的废墟、暗渠集市的氛围）
3. 能凸显角色性格的小细节（如艾莉丝端红茶的动作、「磕哒」的杯底声）
4. 纯装饰性的景物描写——**禁止**，以克制为主，能省则省

**已创作正文中验证有效的文风手段（重点参考）：**
- **「概念命名法」**：主角对现象或势力进行精准命名，既是思考过程展示，也强化了读者的记忆点，如「蝗兵」「滚雪球」「撒币」
- **「外部视角vs内部视角的双层叙事」**：公众面前展示的面孔（新领主/冷静执政者）与读者知晓的真实底牌（改造体军团/预知信息）之间的张力，是爽感的核心来源
- **「冷静收尾反转」**：在强烈冲突后以主角的一句冷静话语或一个不起眼的动作收尾，反差感强化掌控感的塑造，如「他需要的，从来不是所有人的爱戴……他要的是敬畏，与秩序」
- **「数据锚点穿插」**：在叙事中自然插入具体数字（时间、数量、等级、距离），增强真实感和网文读者的沉浸感
- **「空白分隔场景切换」**：时间/空间/视角切换时统一用空行间距（\n\n\n）承载停顿，不加任何分隔线或文字说明，保持正文视觉干净，让场景切换的节奏感完全由空白控制

## 输出格式规范

仅输出以下部分，不附加任何额外标记、说明或分析内容：

```
X：　　标题
[章节正文]

X+1：　　标题
[章节正文]
```

### 格式规则（硬约束）

1. **标题格式**：`[数字序号]：　　[标题名]`——阿拉伯数字 + 中文全角冒号 + 两个全角空格（缩进） + 标题名。示例：`151：　　推演`。不使用「第X章」前缀，标题口语化风格为主。
2. **无结尾标记**：章节末尾不添加任何形式的完结标记（如「第151章完」「本章完」「——待续——」等）。章节自然结束即可，靠章尾钩子收束，不额外标注。
3. **场景切换分隔**：章节内场景/时间/空间/视角切换时，统一使用空行间距分隔，不加任何分隔线或文字说明（详见「章节内场景切换分隔规则」）。
4. **章节间排列**：若要一次性输出多章，两章之间不加额外分隔线或留空，直接连续排列「标题+正文」。
5. **文件命名**：单章正文文件命名为 `第XXX章-标题名.md`，如 `第151章-推演.md`。
6. **字数范围**：单章正文2300-2800字，保持节奏紧凑。

## 核心约束

### 绝对遵循已有设定
- 改造体特性：绝对忠诚但保留自我意识，特性最多对施法者高一阶生效
- 力量体系：属性1点=凡人基准，每提升1点×1.21指数增长
- 金手指状态：预知之环当前不稳定，主角不能依赖
- 断裂的斯诺克法杖：精神力2500%、魔力5000%，但伤害-99%、释放时间+500%
- 改造体数量上限：智力×25（当前上限410名，智力16.4）
- 改造判定消耗：目标体内300%精神力+500%魔力
- 改造时间：智力×300秒（当前约4920秒≈82分钟）

### 角色行为逻辑一致性
- **李星河**：前世博士生的思维习惯（系统化/数据化/实验精神），重生后冷静理性，不冒无意义的险，重视信息和情报胜过蛮力
- **艾莉丝**：月神预备神选者（本人无知），精灵祭司思维（共鸣/频率/自然感知），对李星河有信任和潜在好感但自己不完全承认
- **洛鸢**：洛氏三小姐，商业嗅觉敏锐，在利益和好奇心驱动下主动绑定合作
- **塞瑞娜**：永渊荒野出身的狼亚人逐血猎手，生存至上，对排斥习以为常

### 逻辑驱动
剧情推进力应主要来自：角色的动机（李星河扩张势力、提升实力、保护核心利益）→ 信息的流动（获得新情报→调整策略→行动→获得新情报的循环）→ 资源的限制（精神力/魔力/资金/材料/改造体数量都有明确上限）→ 世界的规则（兽潮威胁/势力平衡/位阶差距）

每一步发展都应能追溯"因为…所以…"的链条。
